# Synthetic workspace calendar isolation candidate

This separate candidate follows `5eebbdc00b220296fd37b7c783532b5240f5a8db` and fixes the inherited ambient Microsoft calendar fallback documented there. No production configuration, real provider, calendar, or booking was accessed or modified.

For an explicitly supplied workspace (including an empty value), a missing or unavailable workspace calendar connection now stops before using either the ambient Graph access token or the global client-credentials flow. A connected workspace continues using its own token. Create, update and delete report failure when no workspace token is available. `/api/calendar/microsoft` reads the caller's authorized workspace status instead of advertising global credentials; POST refuses a missing workspace connection before a provider call or write. Explicit calls with no workspace retain the former global behavior; the separate Studio organizer-bound app-token path remains unchanged. Existing booking create/update/delete calls supply a workspace ID.

The synthetic tests mock all authentication, storage, and provider requests. They cover absent and failing workspace connections against both global credential shapes, blank workspace, valid workspace, both explicit unscoped behaviors, Studio organizer binding, and HTTP status/denial. The previously failing inherited calendar fallback regression now passes and the combined mailbox CI command includes both groups. They do not prove real Microsoft connection availability, safe operation of all legacy calendar routes, or production deployment readiness.

**Remaining availability risk:** `listMicrosoftBusyTimes` still returns an empty list when workspace access is unavailable, and its `meeting-repositories.ts` caller also maps provider errors to an empty list. That can make unknown external busy times appear free for legacy booking availability. This separate issue is not solved by blocking global credential fallback. It must be assessed and fixed or the relevant booking path kept unavailable before relying on external calendar availability.
