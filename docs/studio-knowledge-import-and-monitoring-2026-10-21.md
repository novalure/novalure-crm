# Studio Knowledge: private document transport, initial website import and daily checks

Private document finalization previously compared the Blob SDK's `blob.size` with the authorized document size. In the installed SDK this field comes from HTTP `Content-Length`; it can be absent or describe compressed transfer bytes while the returned stream is decoded. Valid TXT uploads could therefore fail before their bytes were checked. Finalization now retains the MIME check and verifies the actual bounded stream's exact authorized length and SHA256. Ticket, actor, tenant, store, path, expiry and 10 MiB restrictions remain intact.

Saving a website previously created an empty URL draft without fetching content. The new authenticated website-import command uses the existing scanner, scan quota and proposal workflow. It accepts fetched content only into the unchanged initial empty version1 draft. Source/version/URL, original proposal revision, content-only changes and the scan/proposal SHA256 are checked in the same final tenant transaction. No publication occurs. Fetch failures retain the saved source ID and expose an explicit retry action on that entry; existing content and publications continue through ordinary change proposals.

The daily host dispatcher uses the existing cron credential, pause switch and ordinary non-owner RLS runtime. Its server-only nonsecret `NOVALURE_KNOWLEDGE_MONITORING_SCOPES` setting is an exact JSON array of at most three `{workspaceId, sourceId, actorId}` entries; missing configuration enables no sources. A normal persisted MFA-authenticated cookie request must explicitly save an enabled daily configuration. Its audit grant binds the current identity, configurer and configuration revision. The dispatcher validates this durable delegation, current identity/MFA, membership, role, project, source, trusted entitlement and configuration at claim and commit. It retains no personal cookie or login credential. Disabling the schedule or revoking its underlying authority stops subsequent work; ordinary browser logout does not cancel a durable schedule.

Execution is attributed as `DELEGATED_KNOWLEDGE_JOB`, restricted to website scanning and change proposals. Existing authentication, MFA, RLS and the four other cron entries are unchanged. The new cron runs at 06:00 UTC daily. Delegated daily jobs advance to the next 06:00 UTC boundary so a small completion-time offset cannot cause every other day to be skipped. The host starts at most three configured jobs within its 45-second soft budget; the existing scanner has an eight-second network deadline and the route a 60-second platform duration. This is not a claim that every database statement is interrupted by the soft budget.

A website source checks its configured page URL, including bounded safe redirects. It does not crawl every linked page or perform an SEO audit. Detected changes require normal review, approval and publication before assistants use the replacement version.

The Studio deployment additionally requires an explicitly provisioned source scope and an entitlement allowing daily checks. These settings do not raise the existing monthly scan quota. The UI reports dispatcher readiness and prevents enabling an unavailable host through its schedule control. Production setup and the first real run remain separate evidence from local tests.

Targeted validation covers actual SDK streaming/gzip with blocked provider networking, disposable PostgreSQL import/concurrency/security cases, delegated daily authorization/revocation/quota cases, and the actual client component in Chromium with synthetic HTTP responses. Browser UI tests are not authentication, database or provider acceptance. All pre-existing required CI checks remain enabled.
